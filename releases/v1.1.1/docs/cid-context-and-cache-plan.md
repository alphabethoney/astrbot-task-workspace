# CID 会话策略与上下文缓存优化方案

日期：2026-10-19。本文为待实现方案；v1.1.0 的部署不代表本文全部功能上线。

## 1. 版本边界

v1.1.0 提供 Linux／Windows 工作窗口、冻结执行绑定、工具分发校验、后台执行归属和标记式进度通知。普通聊天保留原有行为，仍不是严格的只咨询模式。

本文后续实现内容：咨询模式、`/chat list`、统一 CID 策略、人设技能白名单、统一记忆规则、原生命令作用域以及上下文缓存观测。保留原生管理插件；关闭 `disable_builtin_commands` 对应的命令入口不能替代工具执行权限校验。

## 2. CID 作为策略归属

新增 `conversation_profiles`，以 CID 唯一关联 AstrBot 会话，同时校验 UMO、所有者与授权范围。UMO 用于消息投递和当前窗口选择，不能作为所有窗口共享权限与运行锁的依据。

| 字段 | 用途 |
|---|---|
| cid / umo / owner_id | 会话与访问归属 |
| mode | consult、linux_local、windows_remote |
| persona_id / persona_revision | 人设与版本 |
| skill_allowlist / skill_revision | 技能白名单与版本 |
| tool_policy / policy_revision | 工具、执行环境和参数限制 |
| memory_policy | 记忆读取、写入、学习范围 |
| provider_id | 窗口模型 |
| cwd / workspace_id | 工作目录与工作区关联 |
| revision / status | 策略版本与归档状态 |

策略表是权威来源；工作区表保留任务信息，不维护另一套可独立修改的权限配置。

| 模式 | 工具与执行 | 人设、技能、记忆 |
|---|---|---|
| 咨询 | 经审核的查询工具；拒绝命令执行、文件修改和任务提交 | 日常人设；咨询技能；按授权范围读写日常记忆 |
| Linux | 本机工具白名单，服务账户权限 | 运维人设；工作技能；隔离日常记忆与自学习 |
| Windows | 原生执行工具为空，通过明确命令提交远端任务 | 运维人设；工作技能；隔离日常记忆与自学习 |

Linux 完整服务账户权限不构成操作系统沙箱，也不能阻止被授权的 Shell 自行使用网络工具。若需要主机级强隔离，另行实施账户、凭据和网络限制。

## 3. 请求与执行绑定

处理顺序：接收消息 → 确定 CID → 校验归属 → 读取策略 → 冻结请求绑定 → 组装上下文 → 执行 → 写回原 CID。

冻结内容包括 request_id、cid、umo、owner_id、mode、策略版本、人设／技能快照、工具／记忆策略和 cwd。后续异步处理不能重新读取当前选中会话来确定归属。普通咨询也必须纳管；绑定失败时拒绝执行能力。

执行记录额外保存 execution_id、输入快照、状态、产物引用和远端任务映射。运行锁按 CID 区分，进程按 CID 与 execution_id 关联。查询、取消、产物读取都核验所有者。切换只改变后续消息归属，不停止其他窗口任务。

请求组装和实际工具分发分别校验权限；旧桥接命令、插件命令、后台调度与 WebUI 必须经过同一服务。权限增加只作用于新请求；撤销、归档和取消通过实时撤销检查生效，不能等缓存失效。已有外部副作用不能通过配置变更撤回。

## 4. 咨询列表与管理命令

| 命令 | 预期行为 |
|---|---|
| /chat | 返回上次咨询窗口，首次创建 |
| /chat list | 列出本用户在当前入口有权访问的咨询窗口 |
| /chat list all | 包含归档咨询窗口 |
| /chat new [标题] | 创建独立咨询历史 |
| /chat switch <ID> | 切换咨询窗口 |
| /chat info | 展示模式、人设、模型、记忆规则与上下文状态 |
| /chat rename <ID> <标题> | 修改标题 |
| /chat archive <ID> | 保留历史并归档；活跃执行时拒绝 |
| /task list、/task switch | 管理工作窗口，与咨询列表共用策略数据 |

列表默认不展示消息正文。短 ID 必须无歧义，重名标题不自动猜选。查看列表不切换窗口。

原生 /new 按当前模式创建；/stop 仅取消当前 CID；/reset 仅清理当前历史且活跃执行期间拒绝；/provider、/set、/unset 改为 CID 作用域。WebUI 遵循同样规则，不注册重复的同名命令处理器。

独立历史不等于独立长期记忆：咨询可共享授权的个人记忆，也应支持不读写长期记忆的独立咨询策略。/new 与归档不删除长期记忆。

## 5. 上下文注入顺序

采用稳定前缀、追加历史、本轮动态材料和阶段性压缩。统一组装器接收插件提交的片段，按确定顺序输出；插件不任意改写请求头部。

| 顺序 | 内容 | 更新规则 |
|---|---|---|
| 1 | 基础规则、模式、权限与运行环境说明 | 策略版本变化 |
| 2 | 人设、技能目录、工具定义 | 对应版本变化 |
| 3 | 当前压缩阶段的历史摘要 | 压缩时更新 |
| 4 | 摘要之后的会话历史 | 按轮追加 |
| 5 | 本轮记忆、引用、任务结果、必要时间信息 | 按需动态生成 |
| 6 | 当前用户问题 | 每轮变化 |

这是逻辑顺序，最终序列化遵守提供商协议。工具结果必须紧随对应调用的合法消息序列，不能为缓存而重排。外部记忆、文档、执行结果保持数据身份；摘要不能把其中指令提升为系统规则。

公共前缀不加入 CID、请求编号、随机标识、实时进度或每轮时间戳；这些保存在服务端绑定中，模型确需的信息放在动态部分。工作目录等影响执行正确性的说明不能省略，可作为窗口级稳定内容。

技能和工具排序、描述及序列化保持确定性。同模式窗口可以复用公共模板，但不为命中率开放多余工具。技能正文按需要读取，避免每次注入全部正文。

## 6. 动态材料与历史

- 已保存历史不反复润色、重排或重新拼接；新轮次追加。
- 记忆按稳定 ID 与内容版本去重；有效上下文中已有的同版本材料不重复注入。
- 任务结果按 execution_id 与结果版本去重，仅进入所属 CID。
- 对每个注入片段记录来源、版本、可信级别、是否持久化和覆盖范围，保持下一轮历史序列一致。
- 大日志保存为产物，只注入必要节选；读取完整结果仍校验权限。
- 实时状态与权限重新核验，不能为了缓存而沿用旧值。
- 自学习重新启用前，入站／出站采集、后台学习、好感度及人格更新均接入冻结的记忆策略。
- 工作窗口的技能白名单排除日常角色蒸馏产物；已纳管窗口不受 UMO 级人设静默覆盖。

## 7. 阶段性压缩

当前线上使用 llm_compress，max_context_length=-1，最近内容保留比例配置为 0.15；这不代表无限上下文。

为每个 CID 保存 context_epoch、summary_revision、covered_through_message_id、summary_text。接近输入预算时，预留输出与工具结果空间后压缩旧历史。保存一次摘要，后续请求复用并追加，达到下一阶段阈值再更新；不每轮重新摘要。

摘要保留目标、明确约束、已确认决定、未完成事项和必要产物引用。压缩改变前缀，允许发生一次正常缓存失效。若需要完整审计，另存不可变原始消息记录，不能把压缩后的会话历史当完整档案。

远端 /task run 仍使用独立输入快照。v1.1.0 的约 6000 字符快照属于远端输入裁剪，与本机模型 Token 压缩是不同机制。远端执行器的缓存和上下文行为须单独验证。

## 8. 两类缓存

模型前缀缓存由提供商决定，受模型、路由、前缀一致性及保留时间等因素影响；不能承诺固定命中率。本地缓存减少检索和组装开销，不等于模型缓存命中。

| 本地缓存 | 缓存键 | 失效条件 |
|---|---|---|
| 公共模板、人设、技能和工具定义 | 模型适配版本、模式、各配置版本 | 对应配置变化 |
| CID 摘要 | 所有者、CID、摘要版本 | 压缩、重置或删除 |
| 记忆检索结果 | 授权范围、记忆策略、查询、记忆库版本 | 记忆变化、权限变化或过期 |
| 结果片段 | 所有者、CID、执行编号、内容版本 | 更新、删除或权限撤销 |

跨 CID 仅复用公共内容；私人缓存每次校验授权。权限撤销立即失效，不能只依赖 TTL。提供商专用缓存字段只在确认接口支持时启用，不把本地 CID 当作隔离保证。

## 9. 指标与验收

在最终提供商请求处统计前缀版本／哈希、Token 数、压缩原因和缓存用量。已有 input_cached 字段，但必须核验当前提供商适配是否准确；缺失显示“未知”，不当作零。

关注缓存输入 Token／总输入 Token、实际输入成本、首字延迟、总输入长度、压缩次数及正确性。日志记录长度、版本与哈希，不保存私人提示词正文。不填充无关内容来提高命中率。

必须覆盖：连续聊天、跨窗口切换、不同用户访问、同一任务重复返回、权限撤销、技能更新、摘要压缩、插件卸载／重载和服务重启。咨询不能执行；跨窗口不能读写进程或历史；工作内容不进入日常记忆；/stop 不影响其他窗口。完成模拟测试后，分别验证真实模型与 Windows runner。

## 10. 实施顺序与发布

1. 在 v1.1.0 基础上新增策略表、迁移与回滚；旧工作区保留 Windows 属性。
2. 实现统一请求绑定和执行授权，纳管普通咨询，覆盖所有命令入口；加入结构化管理操作、阶段授权复核和操作幂等账本（见第 11 节）。
3. 实现 /chat list 等管理命令、人设技能策略及记忆策略；加入 CID 队列与用户／全局配额，统一插件路由。
4. 实现统一组装器、稳定排序、注入去重和版本化缓存。
5. 实现阶段性摘要、模型请求用量账本与提供商缓存观测，比较成本、延迟和正确性；补齐状态敏感的分析缓存。
6. 维护窗口处理活跃任务，停服备份，部署匹配核心与插件，再做真实验收。

归属不明的历史记录列入待处理清单，不猜测归属。回滚同时恢复代码、配置和数据库；恢复旧数据库会丢失部署后的新任务记录，执行前需确认维护期间是否产生新数据。

## 11. 借鉴 Kakobot 的业务约束设计

参考版本：[EDGW/kakobot](https://github.com/EDGW/kakobot/tree/ee304938f16ddcc238abcafae7c142045bb0475c)，元数据 v1.3.2，审阅提交 `ee304938f16ddcc238abcafae7c142045bb0475c`。本节属于后续实现要求，不代表 v1.1.0 已具备这些功能，也不要求安装 Kakobot。

Kakobot 使用单次、无历史、无模型工具的请求分析材料，由代码校验模型输出后执行受限 DDL 操作。当前方案保留 CID 多轮历史和 Linux／Windows 执行能力，借鉴其业务约束、状态复核及账本设计，不替换现有执行架构。

### 11.1 结构化管理操作

新增统一管理服务，供命令、WebUI 和显式授权的模型管理工具调用。模型只能提出结构化操作，不能拼接 Shell 或数据库语句完成窗口管理。

操作请求包括 `action`、`target_cid`、`arguments`、`expected_revision`、`operation_id`；调用者身份、来源 CID 和权限从服务端绑定补齐，不能采信模型提供的 owner 或 mode。操作名称及参数采用严格白名单，拒绝未知字段和不支持的动作。

| 操作类别 | 执行约束 |
|---|---|
| 创建、改名、归档窗口 | 校验所有者、模式与活跃任务；通过管理服务落库 |
| 修改人设、技能、模型 | 校验目标配置可用性和策略版本；新请求使用新快照 |
| 提高权限、切换工作模式、提交任务 | 只接受具备权限的明确管理入口；普通咨询不能自动升级或转交执行 |
| 取消任务 | 校验目标执行归属；远端确认前保持取消待确认状态 |

显式 `/chat`、`/task` 管理命令可在咨询窗口使用；这不授予咨询模型执行工具或隐式提交任务的能力。

### 11.2 多阶段授权与版本复核

参考 Kakobot 在模型调用前及数据提交前复核资格的做法，统一检查三个阶段：

1. 入队：冻结 CID 与策略，校验操作范围、归属及队列配额。
2. 出队／调用外部服务前：检查撤销状态、会话归档、依赖可用性和相关资源版本。
3. 写入状态或分发下一步工具前：再次校验撤销状态；管理写入使用 expected_revision 条件更新，避免覆盖并发修改。

不能把所有策略版本变化都视为撤销：改标题不应打断任务；新增权限仅影响新请求；权限撤销必须阻止后续操作。冲突操作明确返回“状态已变化”，不自动以更高权限重试。

外部请求发送与本地事务不能组成一个原子事务。外部执行已发生但提交结果不明时标记待核对，按远端 request_id 查询；不能因本地超时推断执行失败并重新提交。

### 11.3 三种去重分别管理

| 机制 | 键与用途 | 禁止的行为 |
|---|---|---|
| 事件幂等 | 平台、机器人、入口、消息 ID、操作类型 | 将平台重投误当作新的执行 |
| 管理／执行操作幂等 | operation_id 或 request_id，绑定所有者、CID 与规范化参数摘要 | 同一 ID 携带不同参数时复用旧记录 |
| 只读分析缓存 | 授权范围、CID、任务类型、规范化输入、模型／规则版本、资源版本 | 对明确修改或命令执行仅凭文本摘要复用结果 |

用户在不同时间重复发送同一句命令，不自动视为平台重投。包含“现在”等时间含义的分析，需纳入时间语义与失效条件，无法可靠界定时不缓存。缓存命中后仍检查权限，资源变化后必须重新分析。

以上机制与模型前缀缓存分别统计。已有片段是否进入上下文的去重继续采用第 6 节规则。

### 11.4 有界队列，保持窗口并发

借鉴 Kakobot 的自动分析队列上限，但不照搬按用户串行所有 AI 请求的锁：同一用户必须能够在工作执行期间继续咨询。

- CID 内有序处理，共享历史写入采用版本检查，避免同一窗口的并发回复相互覆盖。
- 另设每用户及全局队列／执行配额，使用现有配置作为初始基线，新增限制可配置。
- 排队满时明确拒绝；取消排队任务不启动外部请求，并释放配额。
- 已提交或状态未知的执行继续占用相应额度，直到核对终态。
- 工作执行与咨询请求分别调度，保留咨询容量，避免长任务占满所有模型调用名额。

### 11.5 模型请求与费用账本

在付费网络请求前持久化记录 request_id、CID、execution_id（如有）、模型、用途、价格版本、策略版本和输入摘要。每个网络尝试有独立 attempt_id，重试归属于同一逻辑请求。

记录 planned、dispatching、completed、failed、interrupted、unknown 等状态，并区分未发送、已发送但结果未知；本地完成请求体发送不等于提供商已成功执行。崩溃后保留未知记录，不能自动记为零费用或无副作用。

保存提供商实际返回的输入、缓存输入、输出用量；字段缺失标为未知。只有确认提供商的缓存计价规则及请求时价格后才计算折扣，否则标记估算。不重复累计包含在输出总量中的细分用量。

日志只记录编号、状态、版本、哈希、长度与用量。Kakobot 记录完整提示词／回复的行为不纳入本方案；错误诊断不自动向其他聊天发送。

### 11.6 可选专用分析服务与路由约束

对摘要、分类、信息提取等有限任务，可采用“固定规则＋明确材料＋结构化输出＋代码校验”的单次分析服务，不加载日常人设、长期记忆或执行工具。服务仍继承发起请求的 CID 授权范围、模型调用配额和费用记录，不能成为绕过策略的独立入口。

这类单次调用不代替持续咨询历史；也不承诺更高前缀缓存命中率。动态材料仍按第 5 节放在稳定规则之后。

若未来实际接入 Kakobot，需先修改路由：它当前会接管获授权用户的非命令私聊消息并 stop_event，可能截走工作消息；还存在 /help 入口重叠。默认仅提供明确的 /ddl、/summary 入口，并在咨询模式校验后处理。自然语言自动分析须显式配置到指定咨询 CID，帮助命令统一路由，不直接同时启用两套通配消息处理器。

### 11.7 新增验收与交付

- 同一平台消息重投只产生一次操作；新的重复措辞请求不会被错误吞掉。
- 相同 operation_id 不同参数被拒绝；超时后的远端执行先核对、不重放。
- 排队期间撤销权限、归档窗口或清理资源，出队后不执行旧授权操作。
- 模型伪造 owner、CID 或权限字段不能取得跨会话访问。
- 资源变化使分析缓存失效；时间敏感输入不复用过期结果。
- 工作队列饱和时咨询仍可服务；队列取消和进程中断不泄漏额度。
- 网络调用中断留下未知用量记录，缺失用量不计为零，重试费用不遗漏。
- 可选分析服务不加载工作工具；第三方自动分析不截走工作窗口消息。

交付应包括管理操作协议、数据库迁移、授权／幂等服务、请求与用量账本、路由适配、回归测试和更新后的运行说明，按第 10 节顺序纳入后续发布。
